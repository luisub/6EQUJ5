# Text readability audit — v01

Read-only survey, 2026-11-11, of current data, scene renderers and text helpers. Runtime files were being edited concurrently, so these are time-specific inspection findings and fixture targets; recheck the current implementation before changing anything. No gameplay screenshots or end-to-end readability acceptance were produced.

## Priority cases

1. **Lab choices and scientific qualifiers.** `engine/scenes/lab.py` primary panels slice evidence labels at 38 characters, details at 40, replication prompts at 38, deployment descriptions at 40, impacts at 36 and feedback at 46. `H` exposes full claims, evidence, checks and choice descriptions in a scrollable details view, but at inspection it did **not** include `meter_impact`; a decision's complete consequences therefore cannot be recovered there. Capture advanced FASR-001's 156-character Landauer entropy replication check (ends `>= k_B ln 2`), advanced FASR-002's 174-character eraser detail (selected versus unconditional counts), and FASR-002's second deployment choice, whose 76-character impact ends `Alignment Confidence +5`. Preserve qualifiers, numerical operators, choices and key controls; do not solve clipping by silently deleting scientific meaning. Verify H discovers, scrolls to and closes full content, including feedback and both choice impacts.
2. **Dossier objectives and hints.** `engine/ui/hud.py` renders objective title, description and hint as unwrapped single lines in a left column x28–220 with a right column starting x242. The current Greenkeeper description prefixed `DETAILS:` measures approximately 453 logical px in the current 26-native-px pygame default font versus a 192-px left column, so overlap or clipping is expected. Capture the long boss objective and ACT I completion objective with all inventory and all meters; ensure title, full description, hint, and the second column remain accessible without colliding. This is a measured text-width mismatch, not a screenshot-based observation.
3. **Relay and printout.** `engine/field_reality.py` uses 67-character relay wrapping, retains only eight lines, and slices action labels at 62. Capture the full 1985 first message plus 2031 warning, power and cassette messages and both action options; verify all information and controls remain reachable at actual pixel widths and after failure/recovery. `engine/flashback.py` printout positions are fixed, including the red oval around the signal and the `Wow!` note: inspect before and after annotation with the current proportional font, so oval alignment, scientific characters and close controls remain legible.
4. **Terminal, HUD and transient notices.** Capture a long authored offline response, an input longer than one line with cursor moved to both ends, history scrolled to top/bottom, streaming state, lock/offline status, the full footer, field threat warning and long objective-update notification. The current terminal uses pixel-based transcript wrapping and cursor measurements; verify rather than assume older character-count behavior. HUD intentionally fits location/objective/notification to allocated widths with ellipses. Check a durable way to read any consequential omitted text. Use full-width strings and actual scene measurements; do not assume all labels fit merely because a character count does.
5. **Coverage sweep.** Capture title New/Continue/recovery/error; bunker stations and saving; pause settings/feedback; lab experiment, claim, evidence, replication, deployment, success/error; field/catwalk jam/retry and grapple hints; boss vulnerability/death/retry/victory; annex/relay/1977; CRT on and off. Include native output and integer-scaled presentation, real interactions where practical and fixtures explicitly labeled. Check text contrast and controls as well as bounding rectangles.

## Glyphs and encoding

Actual non-ASCII in JSON string values scanned under `data/` and `assets/civilizations/manifest.json`: `σ` U+03C3 (lab evidence; also terminal peak and dish status in code); `ö` U+00F6 (Göbekli name in mission/dialogue data); `°` U+00B0 and `±` U+00B1 (civilization manifest); en dash `–` U+2013 and em dash `—` U+2014 (civilization manifest; em dash also separates H-view evidence/choice). The manifest inventory does not by itself prove all metadata is displayed at runtime. Source UI also uses `·` U+00B7 for meters and symbols `▶ ✔ ■ ● ○ ▌ →`; the inspected renderer maps the latter seven to ASCII equivalents before drawing and measuring. Preserve meanings when mapping UI symbols; do not silently substitute scientific symbols or change inequalities, units, names, or typography that carries meaning.

With pygame-ce 2.5.8, `pygame.font.Font(None, 26)` `metrics()` reported distinct entries for `σ ° ± ö – — ·`; this is an availability check in the local default font, not visual proof at scene scale, not proof of coverage on other font builds, and not a test of every live-model character. User/model input can include further Unicode.
