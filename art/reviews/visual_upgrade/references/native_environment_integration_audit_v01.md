# Native approach family — read-only integration audit v01

2026-11-11. Reviewed `briefs/approach_asset_transaction_contract_v01.md`, `engine/asset_transactions.py`, `tools/build_assets.py`, `main.py`, `world.py`, field/boss/timeline rendering, CRT compositor, relevant existing tests and `pyproject.toml`. This is an inspection of the current code, not an implementation, transaction execution, wheel build or visual acceptance. Technical changes may be in progress; recheck the current files before acting.

## Transaction and path risks

1. **New family is outside the 14-group protection.** `ALL_GROUPS` is 11 civilizations plus Mateo, bunker and review; `_group_paths`, `_validate_inputs`, `_render_group`, `_validate_outputs` and CLI choices are hard-coded for them. A current dry-run cannot establish the presence, hash, completeness or protection of an approach family. If adding an optional family to `ALL_GROUPS`, note `_build_selected_groups` plans an absent unlocked group even without `--replace`: simply extending the tuple can cause an unintended default first promotion. Require explicit family selection and test default, dry-run, partial and present-family behavior.
2. **The low-level promoter does not take the directory lock.** `build_selected_groups` acquires nonblocking `fcntl` lock on the asset-root directory and holds it over recovery, preflight, staging and promotion; `promote_group` assumes its caller has done so. Startup `recover_before_load` acquires the same lock only while recovering; it does not keep a running game's reader lock. Do not build/promote during an active game; a journaled series of replacements is not a single atomic group swap. File writes and the journal use existing behavior; directory fsync, power loss, non-macOS locking and concurrent-live-reader safety are not established.
3. **Validate staged and target paths, including symlinks.** `promote_group` rejects absolute paths and `..`, checks `target.resolve()` stays within `asset_root`, and verifies staged `is_file()`. It does not check that `source.resolve()` stays in `stage_root`; `is_file()` follows a staged symlink. Existing target symlinks can also be followed for backup yet replaced as directory entries, changing restoration semantics even when the resolved target is inside root. Reject symlink components/leaf and duplicate output or manifest references, or use a stronger pinned/contained scheme. Validate untrusted manifest references before reading. Resolve and containment-check staged inputs and archive policy; test escaping links, in-root links and duplicate paths. Do not infer that legacy helpers already guarantee symlink safety.
4. **Recovery and code deployment are distinct.** Archive and verify pre-existing untracked code separately before editing. Stage all selected family images and manifest, validate all and promote as one logical journaled group under the same lock, manifest last; record files formerly absent and byte hashes. Failure tests should interrupt after each replacement and confirm rollback removes formerly absent files and restores existing hashes. Existing tests cover legacy FASR-001 injected failure and child-process crash; they are not new-family coverage. `_restore` assumes its journal entries/archive are valid and does not itself revalidate all path/symlink properties; do not treat a writable or forged journal as a security boundary. If backup hash validation fails, fail closed and retain recovery material.
5. **Recovery entry points matter.** `main.run_game` and `tools/preview_assets.py` invoke `recover_before_load`; code that constructs `GameStateMachine` directly (including some fixture/capture tools) does not automatically do so. Document and test such tools with isolated temporary asset roots or an explicit safe recovery call, rather than asserting universal startup recovery. Code resides outside the asset-root journal; code/art replacement is not an atomic transaction. A read-only installed package may not permit recovery writes, so check installed launch and report its limits rather than assuming write capability.

## Render routing and validation

- `Room.render_background(surface, camera)` currently receives only the logical Pygame surface and resolves hard-coded Ohio assets by bare filename. `FieldOpsScene` uses this path for normal rooms; `BossScene` and `MandelaWorld.render` separately call room rendering. A native compositor needs access to the CRT object without making the new family global, accidentally duplicating legacy reflector/fence, or bypassing timeline/boss fallbacks. Explicitly gate by `room_id == act_01_approach`, including reentry/Continue and non-approach scene transitions. Maintain a complete legacy stack for missing/invalid family; don't draw one new layer before validating/decoding all required layers and then silently mix it with fallback. Emit a useful once-per-load diagnostic, not per-frame disk reads.
- Legacy `_ENV_CACHE` is keyed by bare name and caches `None` for a missing/bad file; no-display calls return `None` without caching. New cache keys should identify family/path and immutable version or have a deliberate invalidation policy. Test absent → installed/reloaded, bad hash/dimensions/alpha/PNG, incomplete manifest, room switches, fallback → valid and vice versa. Avoid stale cross-root test cache; cached surfaces must not mask a later repaired family. Validate actual image bytes/hash, decoding, declared dimensions, roles/order/density, alpha mode and coverage before exposing the family.
- Current density is 2, viewport 480 × 270 and room 960 × 288. Camera clamps x=0–480, y=0–18 (floating values possible). Far plate 1152 × 544 sampled at `(round(0.2*cx), round(0.1*cy))` has max crop origin (96,2) and right/bottom (1056,542), within bounds. World layer 1920 × 576 sampled at `(round(2*cx), round(2*cy))` reaches origin (960,36), right/bottom exactly (1920,576). Test both endpoints, fractional-camera rounding and world/screen phase, no wrap, vertical extremes and native 1-pixel details. World geometry uses its own `round(wx-camera.x)`; a fractional camera can reveal phase differences that endpoint-only captures miss.
- Preserve compositing order: native far, native architecture, actual collision tiles/objects, enemies/telegraphs, original Mateo sprite/projectiles/effects, weather, HUD. `CRTRenderer.composite_native` flushes pending logical drawings before adding the native layer; drawing native content at the wrong time can put it over tiles or HUD. Validate with tiny colored/alpha sentinel layers and high-frequency pixels, plus actual-room captures; file loading and mocked call counts alone do not prove z-order, alpha blending or preserved native density. Keep cache/load work off the per-frame critical path and measure performance separately.

## Packaging and verification

`pyproject.toml` explicitly declares `video_game = ["assets/**/*", "data/**/*"]` with `include-package-data = false`, and excludes `video_game.art`, planning, tests, `_trash` and `_temp` from package discovery. The glob is intended to include nested `assets/environments/ohio_approach_v1/manifest.json` and PNGs, but this source inspection does not establish which exact members a newly built wheel contains. Build one clean wheel after integration, inspect exact nested family members and hashes plus excluded source/review material, install into a temporary target and launch from outside the checkout with dummy SDL and temporary saves. Verify the installed loader reads the installed package, not repository paths. No build was run during this audit.

Minimum focused checks: explicit-only promotion; file/path/hash/alpha/dimension validation; missing/corrupt full fallback; staged and target symlink/duplicate rejection; locked-group invariants; lock contention; interrupted transaction recovery and absent-file cleanup; native crop coverage/z-order at camera extrema and fractions; approach-only routing, normal reentry/Continue and unchanged boss/yard/prototype scenes. Then run the prescribed offline suite, content validator, relevant new-family and legacy dry-runs and clean-wheel smoke. Static captures, successful unit tests and the legacy 14-group count do not certify human art/playability or native graphical performance.
