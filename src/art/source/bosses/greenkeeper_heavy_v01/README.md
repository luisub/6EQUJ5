# Greenkeeper heavy v1 source and restoration

Four separately generated key poses: idle, mortar attack, exposed reactor, and wreck. Later poses were edited from the idle master. This is four key poses, not an eleven-frame animation family; charge uses idle and the attack key is reused for the sweep. There is no new animated track cycle. Nearest-neighbor export at 256×192 preserves crisper pixel edges with some fine-detail aliasing. The original masters, exact prompts, generated-image provenance, exports and optional Lanczos alternatives are retained here; historical review fixtures are under `_trash/2026-11-13_separation/historical-reviews/art/reviews/visual_upgrade/previews/greenkeeper_heavy_*`.

`python -m video_game.tools.build_greenkeeper_heavy --source src/art/source/bosses/greenkeeper_heavy_v01/exports --promote` validates the four reviewed files and installs them under `assets/sprites/bosses/greenkeeper/` through the shared lock, stage, archive, journal and manifest-last transaction. The install archive manifest records the files as newly created and how to restore; it is `video_game/_trash/2026-11-11_F03/feac5ccd831e4704b4686d5524727991/manifest.json`. Preserve that archive. The old eleven-frame bitmap family is preserved under `_trash/2026-11-14_asset_layout/src/assets/sprites/bosses/greenkeeper/`. An absent, incomplete or corrupt current family selects the existing 64×48 procedural fallback on encounter construction.

Each PNG is 256×192 native RGBA, 128×96 world, foot baseline y=96; nominal world origin (428,144), foot y=240. Idle/exposed muzzle approx (38,15), attack muzzle (39,16), wreck muzzle (35,40), sweep source (5,80), exposed core rectangle (62,49,23,19), all local world units. Position and target must remain tied to moving boss. Detailed presentation and gameplay acceptance are separate; fixture screenshots alone do not establish native-window human-play acceptance.

The seven one-off candidate preparation/arena scripts were archived during repository cleanup. Their exact paths and hashes are in `docs/maintenance/archive-manifest.json`. Use the maintained builders and runtime capture tools for new work.
