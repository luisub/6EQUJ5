# Greenkeeper heavy v1 source and restoration

Four separately generated key poses: idle, mortar attack, exposed reactor, and wreck. Later poses were edited from the idle master. This is four key poses, not an eleven-frame animation family; charge uses idle and the attack key is reused for the sweep. There is no new animated track cycle. Nearest-neighbor export at 256×192 preserves crisper pixel edges with some fine-detail aliasing. The original masters, exact prompts, generated-image provenance, exports, review fixtures and optional Lanczos alternatives are retained here and under `art/reviews/visual_upgrade/previews/greenkeeper_heavy_*`.

`python -m video_game.tools.build_greenkeeper_heavy --source video_game/art/source/visual_upgrade/candidates/greenkeeper_heavy_v01/exports --promote` validates the four reviewed files and installs them under `assets/sprites/bosses/greenkeeper_heavy_v1/` through the shared lock, stage, archive, journal and manifest-last transaction. The install archive manifest records the files as newly created and how to restore; it is `video_game/_trash/2026-11-11_F03/feac5ccd831e4704b4686d5524727991/manifest.json`. Preserve that archive. The original `assets/sprites/bosses/greenkeeper/` family and its manifest are unchanged. An absent, incomplete, or corrupt heavy family selects the full legacy geometry and art path on encounter construction.

Each PNG is 256×192 native RGBA, 128×96 world, foot baseline y=96; nominal world origin (428,144), foot y=240. Idle/exposed muzzle approx (38,15), attack muzzle (39,16), wreck muzzle (35,40), sweep source (5,80), exposed core rectangle (62,49,23,19), all local world units. Position and target must remain tied to moving boss. Detailed presentation and gameplay acceptance are separate; fixture screenshots alone do not establish native-window human-play acceptance.
